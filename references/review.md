# 逐条拉片与账号归纳

## 核对声音与画面

每段三帧标出采样时刻。快速运动、闪光、转场、画中画会诱发误切，缓慢溶解或同色硬切可能漏切。需要修正边界时修改 shots.json，并重新抽取该段对应时码的帧、更新 frames 与 sample_times 后渲染。没有逐帧确认的边界注明自动候选；同一运镜被误切时注明“同一动作的延续”。

在 analysis/<作品ID>/review.json 中用镜号作键，下例只展示格式。action 和 camera 填所见，function 填它对观众预期的作用，caption 只填画面字，sound 只填可辨的声音。speech 仅在需替换对齐文本时填写；留空键值表示该镜确认无对白。无此键时按转写时间对齐。

```json
{"1":{"action":"电梯门打开，纸箱自行滑入。","camera":"贴地固定近景","function":"先见结果，延迟两秒揭示是谁推的","caption":"三楼","sound":"电梯提示音","boundary":"回放确认"}}
```

转写含识别错误时，把首次识别留作 transcript.raw.json，再修订 transcript.json 的 segments（start/end/text，可选 words）。校订过文本而沿用旧字级时间会让分镜复现错字；重新对齐，或去掉该句 words，采用句首对齐。保留机器初稿、已对照字幕、听辨待核等状态。音乐或语气词不凭模型幻读扩写；机器返回无语句时先听辨，再区分无对白、音乐或识别失败。如果检测为异常语言，结合实际原声与画面字决定是否按已知语种重识别。

macOS 上可选用本 Skill 的 ocr.swift，对原片每半秒读取一次屏幕文字。先将它编译到临时目录，再对目标原片运行：`swiftc "$HERE/scripts/ocr.swift" -o "$TMP/ocr"`，`"$TMP/ocr" "$MP4" > "$SHOT_DIR/ocr.jsonl"`。每条的 t 是秒数，归一化 y 从画面底部起算。包装字、声明、字幕需人工分辨，画面字自身不足以证明有人说过。

## 跨片比较与创作迁移

- 公开事实来自账号资料。受众以观看动机、使用场景和期待回报描述；年龄、地域、性别等只有在确有后台或其他明确证据时再写。演员、演员扮演的角色、账号自述身份、品牌是不同实体。
- 每条留一个内容标签，方便检索通用标题。写出首帧的异常、观众的第一个猜测、揭晓点和创作者如何兑现；区分不同类型作品。一个模板只出现一次时可以保留为试验方向。
- 给规则配两条样本时码；只有一例就写清特例。用秒段和发生条件说节奏，有音乐或声音设计只在听辨支持时指认。公开互动量若用于比较需附采样时间，播放量和粉丝画像缺失时留空。
- 子 Skill 必须能回答“谁会想看、哪种角色负责推动、第一镜拍什么、转折由哪个动作造成、换商品或题材后还成立吗”。选题示例用新账号的独立身份、原创台词和新场景。输入是产品时先写功效和第一镜；输入是非商品账号时按素材里的叙事或信息价值来构建。
